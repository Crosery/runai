inputs: 用户描述的问题 / 现象 / 故障 / 探索目标
outputs: 因果溯源报告 + 规格说明书 (spec) + 可接 plan / autopilot
---

## 使用场景

当用户描述一个问题或目标，但根因不清晰时，先做溯源调查
再精准定义需求，避免基于错觉症状做错决策。

## 流程

1. 三点注入：在用户上下文中插入 3 个并行的根因假设
2. 平行调查：每个假设独立 grep / read / test 验证
3. 因果合并：把验证下来的 fact 收敛成单一根因
4. 需求重提：基于根因输出 spec，标注哪些是必做、哪些可延后
5. 对接执行：spec 直接喂给 plan / autopilot
